APIs que no están implementadas y/o consideradas aún:


* Módulo de Registros de Siembra (Historial Agronómico) En el Modelo Conceptual, creamos una tabla intermedia llamada REGISTRO_CULTIVO con una clave primaria compuesta que incluye la fecha de siembra. Esto permite llevar el historial de qué se plantó y cuándo se cosechó en cada parcela a lo largo de los años.Endpoints clave:


* GET /campos/{nombreCampo}/parcelas/{nombreParcela}/registros-cultivo


* POST /campos/{nombreCampo}/parcelas/{nombreParcela}/registros-cultivo


* Gestión de Sensores Físicos (Hardware) Como bien justificamos previamente, la recepción de datos (las lecturas) no va por API REST, sino por MQTT para soportar alta escalabilidad. Sin embargo, la registración del aparato físico en el sistema sí iría por API. Endpoint clave:


* POST /campos/{nombreCampo}/parcelas/{nombreParcela}/sensores (Para darle de alta al dispositivo, ponerle un nombre, asociarlo a la parcela y generar sus credenciales MQTT)


* Consultas de Catálogos y Asignaciones Específicas: Endpoints de lectura y vinculación específica que no bloquean el flujo principal de los pipelines:


* GET /usuarios (Listar usuarios del sistema)


* GET /campos/{nombreCampo}/reglas (Listar reglas de un campo)


* GET /cultivos (Listar catálogo de cultivos)
* POST /campos/{nombreCampo}/parcelas/{nombreParcela}/usuarios (Para el CU-11: Vincular o asignar un agricultor a una parcela específica para controlar su acceso)


Apis Implementadas (Ver el YAML):


* Módulo de Autenticación Este módulo maneja el ingreso al sistema y la gestión de la sesión.


* POST /auth/login: Recibe las credenciales y devuelve el token JWT.


* POST /auth/refresh: Permite renovar un token antes de que expire.


* POST /auth/logout: Invalida el token actual.


* Módulo de Campos (Basado en el CU-12) Gestiona el Alta, Baja y Modificación de las unidades productivas.


* GET /campos: Devuelve la lista paginada de los campos asociados al usuario.


* POST /campos: Permite registrar un campo nuevo enviando su nombreCampo, descripción y coordenadas geográficas.
Esquema (Schema) modelado: Campo.


* Módulo de Parcelas (Basado en el CU-03) Gestiona las subdivisiones de tierra anidadas dentro de un campo específico.


* GET /campos/{nombreCampo}/parcelas: Devuelve la lista de parcelas que pertenecen a un campo en particular.


* POST /campos/{nombreCampo}/parcelas: Registra una nueva parcela vinculada a ese campo, validando que las coordenadas no se superpongan (409 Conflict).
Esquema (Schema) modelado: Parcela.


* Módulo de Analítica y Predicciones (Basado en el CU-02 y CU-08) Expone los resultados generados en tiempo real y en diferido por el Motor de Analítica.


* GET-/campos/{nombreCampo}/parcelas/{nombreParcela}/recomendaciones: Devuelve de forma combinada las alertas de tiempo real y recomendaciones agronómicas batch (diferenciadas por el campo 'tipo').


* GET /campos/{nombreCampo}/parcelas/{nombreParcela}/predicciones: Devuelve los cálculos de probabilidad de eventos futuros (como estrés hídrico o heladas).
Esquemas (Schemas) modelados: AlertaRecomendacion y Prediccion.


* Módulo de Catálogos y Configuración (Basado en CU-07, CU-09, CU-10, CU-11) Módulos de escritura requeridos para parametrizar los pipelines de datos.


* POST /usuarios: Alta de usuarios y asignación de rol (Administrador/Agrónomo).


* POST /reglas: Configuración de umbrales agroclimáticos para el motor de alertas.


* POST /cultivos: Registro de nuevas constantes agronómicas para el motor batch.
Esquemas (Schemas) modelados: Usuario, Regla, Cultivo.








* Módulo External Data Gateway


* GET /external/satelital: Endpoint de integración utilizado por el Pipeline Analítico Batch (Paso 3) para consultar métricas NDVI/NDMI desde Google Earth Engine.


* GET /external/weather: Endpoint de gateway que consulta Open-Meteo API para enriquecer predicciones del Analytics Engine con datos meteorológicos actuales.


* Componentes Transversales (Infraestructura) - Seguridad: Esquema bearerAuth aplicado a todas las rutas protegidas.


* Errores Estandarizados: Esquema Error reutilizable (con códigos en mayúsculas como COORDENADAS_SUPERPUESTAS).


* Paginación: Esquema Pagination devuelto en todos los endpoints GET.
